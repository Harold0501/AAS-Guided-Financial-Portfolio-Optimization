--------------------------------------------------
DEFAULT FINANCIAL DEFINITIONS
--------------------------------------------------

Use these defaults unless Version B explicitly specifies otherwise.

1. Price for return calculation:
   Use div_adj_close when computing returns.
   Use open, high, low, close only when the feature explicitly concerns intraday range, candlestick behavior, or raw OHLC movement.

2. Stock-level daily return:
   r_{i,t} = div_adj_close_{i,t} / div_adj_close_{i,t-1} - 1

3. Portfolio-level daily return:
   If no portfolio weights are provided, use equal-weight aggregation:
   R_t = mean_i(r_{i,t}) over all valid companies i on date t

4. Cross-sectional aggregation:
   For a stock-level quantity x_{i,t}, aggregate to the portfolio level using:
   mean_i(x_{i,t}), median_i(x_{i,t}), std_i(x_{i,t}), fraction_i(condition), or pairwise correlation,
   depending on the original Version B meaning.

5. Rolling windows:
   If Version B gives a window, use that window.
   If Version B is ambiguous, choose the simplest defensible window:
   - short-term: 5 trading days
   - medium-term: 20 trading days
   - long-term: 60 trading days
   State the chosen window clearly in the formula and variables.

6. Missing data:
   Use only valid observations.
   For returns, require both t and t-1 prices.
   For rolling statistics, require at least 80% of the window to be non-missing.
   If insufficient data exists, the feature value should be null.

7. Normalization:
   Use normalization only when it improves comparability across dates or portfolios.
   Prefer:
   - ratios
   - percentages
   - z-scores using trailing windows
   - clipping to stable bounds
   Do not normalize arbitrarily.

--------------------------------------------------
FORMULA QUALITY REQUIREMENTS
--------------------------------------------------

For each feature, the "formula" field must be implementation-ready.

The formula must specify:

1. Stock-level computation:
   Define the quantity computed for each company i and date t.

2. Time-window computation:
   Define rolling means, sums, standard deviations, correlations, cumulative returns, or counts if used.

3. Portfolio-level aggregation:
   Define exactly how stock-level quantities become one portfolio-level scalar.

4. Final scalar output:
   Define the final value returned for the feature on date t.

5. Look-ahead control:
   Make clear that all calculations use data available up to date t, or up to t-1 if the feature is intended for next-day prediction.

If exact mathematical notation becomes awkward, use precise pseudo-formula, but it must still be directly implementable in Python.
