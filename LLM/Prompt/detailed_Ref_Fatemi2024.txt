--------------------------------------------------
DEFAULT IMPLEMENTATION ASSUMPTIONS
--------------------------------------------------

Use these assumptions unless the original feature clearly states otherwise.

1. Date ordering:
   Sort data by company and date before all calculations.

2. Price field:
   Use div_adj_close for return-based features.
   Use open, high, low, and close only for intraday range, candlestick, or OHLC-based features.

3. Portfolio aggregation:
   Because external portfolio weights are unavailable, use equal-weight aggregation across all valid companies.

4. Stock-level to portfolio-level conversion:
   First compute the relevant stock-level quantity for each company.
   Then aggregate across companies using a clearly specified method such as:
   - mean
   - median
   - standard deviation
   - fraction satisfying a condition
   - average pairwise correlation
   - percentile spread
   Choose the aggregation that best matches the original feature meaning.

5. Rolling windows:
   If the original feature specifies a window, keep that window.
   If the original feature is ambiguous, use:
   - 5 trading days for short-term behavior
   - 20 trading days for medium-term behavior
   - 60 trading days for long-term behavior
   State the selected window explicitly in the procedure.

6. Missing data:
   Use only companies with valid required fields.
   For rolling windows, require at least 80% valid observations.
   If insufficient data exists, return null for that date.

7. Output timing:
   Define the feature value at date t using only data available on or before date t.
   If the feature is intended as input for next-period prediction, state that it should be computed at t and used to predict t+1.

If a feature refers to unavailable information, reinterpret it conservatively using only the allowed fields.

Do not introduce macro, news, sector, valuation, or sentiment interpretations.
